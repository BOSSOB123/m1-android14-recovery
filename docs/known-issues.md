# 验证矩阵与后续工作

这里区分用户反馈、工具核验、局部系统调整和未测项。用户报告“目前可正常使用”是日常可用性反馈，不替代逐项测试。

| 项目 | 状态 | 证据与限制 |
| --- | --- | --- |
| Android 14 开机 | 已验证 | 用户看到安卓；API 34、boot_completed=1 |
| system 写入 | 已验证 | 与源镜像等长完整读回，SHA256 一致 |
| GPT / vbmeta 保持 | 已验证 | 写前后哈希一致；未写 boot/vendor/recovery/dtbo |
| 新 data 与加密 | 已验证 | 数据挂载，记录为 FBE；原用户数据已按授权丢弃 |
| Wi-Fi 状态与 HTTPS | 已验证到部分范围 | 时钟纠正后真实 HTTPS 成功，联网状态 VALIDATED；非全网站可达证明 |
| 屏幕触控/基本操作 | 用户可用反馈 | 能完成基础设置操作，未做完整触控测试 |
| 性能 | 有改善但仍卡顿 | 动画缩短；短样本仍有明显 jank，缺少长期对照 |
| 前摄按钮闪烁 | workaround | GPU 合成测试后用户确认停止；持久性未单独跨重启验证 |
| 保存照片/录像方向 | 未完整验证 | 尚无完整系统级方向修复验证 |
| 扬声器/音频路由 | 未完整验证 | 没有系统性测试矩阵 |
| 蓝牙 | 已知异常 | 启动记录有 native 服务断言崩溃，尚未修复/验收 |
| Android 11 回退 | 材料核验、未实测 | 不保证回刷后可启动，不恢复旧个人数据 |
| 休眠/电池/充电/长期稳定 | 未系统验证 | 缺少持续测试，GPU 合成可能增加功耗 |
| 同型号其他批次 | 未验证 | 当前样本数为 1 |

## 适合后续贡献的工作

1. 添加不同硬件修订的脱敏资料，先读不写，建立真正的兼容矩阵。
2. 查清蓝牙 HAL/框架兼容问题，记录可恢复的实验。
3. 分别测试前后摄预览、照片、录像与 EXIF 方向。
4. 测试待机、唤醒、热量和 GPU 合成功耗。
5. 在有完整备份和明确授权的条件下演练回退；失败记录也应保留。
6. 评估维护中的新镜像；不能凭“更高 Android 版本”跳过安全补丁、旧 vendor 和启动链检查。

不承诺发布时间或远程代刷服务。提交问题前请阅读 [贡献要求](../CONTRIBUTING.md)。
