# 恢复准备与回退边界

本例全程只针对机主自己的已解锁设备。仓库不提供解锁授权、账户绕过或他人的设备密钥。

## 写入前保留什么

| 材料 | 用途与限制 |
| --- | --- |
| 当前可用 system 的完整镜像 | 系统回退候选；SHA256 和只读文件系统检查要通过 |
| 原厂 system / vendor | 辅助恢复和比对，不能混用其他批次固件 |
| boot、recovery、dtbo、当前 vbmeta | 保留与本设备匹配的启动链材料 |
| 主/备 GPT | 核对分区边界与结构；GUID 可能识别设备，不要公开 |
| 当前 metadata 与一致的 userdata | 含加密状态及私人资料；必须配套考虑，单独 metadata 不能恢复个人文件 |
| 原机 boot1 的私密备份 | 本例从中取得 EMI 初始化 DRAM；不是刷入 preloader 的许可 |

备份须包含来源、长度、采集状态、校验和及是否完整。不要公开原始备份，也不要把别人的 boot1、NVRAM、NVDATA、密钥或身份分区写进自己的机器。

## 独立通道

这台机器的常规 fastboot 工具曾出现超时。最终使用 MTKClient 的原生串口 Preloader/XFLASH 通道。使用版本记录为 `7cb40e727727dfe3faa065eefb29b16ed29bbdf1`；应先确认上游仓库能解析此提交及本机依赖，不能假定最新版本行为完全一致。

物理进入底层模式采用过连接 USB、配合音量减和电源复位的方法。不同电源状态会进入正常启动、菜单或底层模式，**黑屏不等于已连接成功**。必须用实际 USB 枚举、握手、芯片/存储检查和只读 GPT 读取判断。不要在仍写入或校验时按电源。

原始工作脚本存在设备标识和本机路径，因此不公开。串口问题与修正思路见[刷写文档](flashing.md)，不能跳过身份与分区检查直接复用偏移。

## 回退不是无损撤销

本例保留 Android 11 clean system，精确 4 GiB，并通过本地哈希和文件系统检查。**尚未实测从 Android 14 回退到它并成功开机。**

回刷旧 system 不会自动将新建的 FBE data 变回旧 FDE data。既有应用、账户和个人文件已按用户授权丢弃，没有完整用户数据快照，不能恢复旧个人数据。Android 14 首次启动也会改变 data。

原厂 vbmeta 与当时 Android 11 配套的 vbmeta 配置不同。不能因为文件名写着“原厂”就直接替换当前 vbmeta，更不能在自定义 GSI 仍存在时重新锁定 bootloader。

## 明确不做的事

- 不在挂载中的 `/dev/root` 上在线覆盖 system。
- 不改分区表，不套用其他机型 boot/vendor/preloader。
- 不发布清空 data 的默认脚本。
- 不把残缺分区镜像、工具成功提示或未启动验证的材料叫作“已经可以保证救回”。
